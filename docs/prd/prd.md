# PRD v0.3：Agentic Coding Learning Coach

## 1. 文档目的

本文档只描述产品需求：产品为谁解决什么问题、用户如何完成核心流程、第一版应该交付什么、不做什么。

具体技术架构、数据库设计、Agent 状态机、RAG、工具层、Trace、Docker 和工程任务拆分不放在本文档中，分别以架构文档、实施计划和 `docs/project-todolist.md` 为准。

## 2. 产品一句话

Agentic Coding Learning Coach 是一个面向算法刷题的 AI 教练。

它不把自己定位成“答案生成器”，而是帮助用户明确训练目标、生成训练计划，在做题过程中通过追问、分层提示、代码 review 和复盘，把一次刷题变成可诊断、可追踪、可改进的训练闭环。

## 3. 用户与问题

### 3.1 目标用户

**刷题入门者**

- 看完题目后不知道从哪里开始。
- 不熟悉常见题型、数据结构和复杂度分析。
- 容易直接看答案，缺少独立推导过程。

**刷过一轮但想提升的人**

- 能看懂题解，但独立做题不稳定。
- 面试时表达思路、复杂度和边界条件不够清晰。
- 常在实现细节、边界条件、调试和复盘上重复犯错。

### 3.2 核心痛点

用户刷题时最缺的不是“最终答案”，而是一个稳定的训练过程：

- 今天应该练什么。
- 卡住时应该先想什么。
- 什么时候需要提示，提示应该给到什么程度。
- 代码错了以后，应该定位思路问题、实现问题还是边界问题。
- 做完一题后，应该沉淀哪些经验，并决定下一题练什么。

普通大模型可以回答问题，但太容易直接给完整解法。这个产品要把 AI 约束成教练：先诊断，再引导，最后复盘。

## 4. 核心用户故事

### 4.1 首次进入：先明确目标

用户第一次进入产品时，先完成基础设置和目标校准：

1. 注册或登录本地账号。
2. 配置自己的 OpenAI / OpenAI-compatible API 资产。
3. 填写当前水平、训练目标、面试时间线、每周投入时间、默认训练语言和自评弱项。
4. AI 可以追问少量关键问题，帮助确认目标。
5. 用户确认后，系统生成第一版学习计划。

用户此时应该得到一个清楚的答案：接下来为什么练这些题、按什么阶段练、每个阶段重点补什么。

### 4.2 开始训练：从计划进入工作台

用户从当前学习计划中选择一道题进入做题工作台。

工作台应同时提供：

- 左侧中文题面。
- 右侧 ChatGPT 式 AI 教练对话区。
- 当前训练模式。
- 提示档位。
- LeetCode 原题入口。
- LeetCode 提交结果回填入口。

用户主要在工作台里阅读题目、描述思路、粘贴代码并接受 AI 教练引导。真正的代码编写、运行和提交以 LeetCode 官网为准，产品不做本地代码执行。

### 4.3 卡住时：AI 先追问，再提示

用户可以向 AI 描述自己的思路、卡点或代码问题。

AI 默认不直接给完整答案，而是先判断用户卡在哪里：

- 没理解题意。
- 没识别题型。
- 不知道暴力解法。
- 不知道如何优化。
- 不清楚关键不变量。
- 漏了边界条件。
- 代码实现有 bug。
- 复杂度分析不准确。

AI 根据卡点决定下一步动作：继续追问、给方向提示、给关键提示、review 代码，或进入复盘。

### 4.4 代码 Review 与提交反馈：以 LeetCode 结果为准

用户在 AI 教练对话中说明自己的解题思路。AI 可以先追问“你的暴力解法是什么”“你准备维护什么状态”“边界条件有哪些”，再引导用户给出代码片段或完整代码。

AI review 代码时，应优先说明：

- 当前代码的主要问题类型。
- 问题大致发生在哪个逻辑区域。
- 为什么这个问题会导致错误。
- 用户应该优先检查哪个输入或边界。

AI 不应默认直接重写整段可提交代码。只有在高提示档位或复盘阶段，才可以解释完整思路。

当 AI 认为用户已经有可尝试的方案时，应建议用户去 LeetCode 官网提交。用户把 AC、WA、TLE、RE 等结果回填到产品中，AI 再根据用户描述、代码和提交结果继续 review 或进入复盘。

产品第一版不做本地代码运行、不提供样例执行结果、不自建判题能力。训练反馈以用户在 LeetCode 的提交结果为准。

### 4.5 做完以后：复盘并推荐下一步

一道题结束后，系统生成单题复盘：

- 本题最终结果。
- 用户主要卡点。
- 使用过的最高提示档位。
- 代码错误类型。
- 时间复杂度和空间复杂度。
- 本题真正需要掌握的核心思路。
- 对用户学习画像的更新。
- 下一题或下一组训练建议。

用户应该能看懂：这题不是简单地“做过了”，而是对自己的能力画像产生了什么影响。

## 5. 核心流程

第一版要跑通以下闭环：

```text
目标校准
-> 生成学习计划
-> 选择题目
-> 进入做题工作台
-> 用户描述思路或写代码
-> AI 诊断卡点
-> AI 追问或分层提示
-> AI review 代码
-> AI 建议用户去 LeetCode 提交
-> 用户回填 LeetCode 提交结果
-> 单题复盘
-> 更新学习画像
-> 推荐下一题
```

这个闭环是第一版的产品主线。其他能力如果不能服务这条主线，都不应优先进入第一版范围。

## 6. 训练模式

### 6.1 入门引导模式

适合刚开始刷题的用户。

AI 可以更主动地拆题、解释题意、提醒常见题型，并引导用户先写暴力解法，再逐步优化。用户连续卡住时，可以更快提升提示档位。

### 6.2 独立训练模式

适合已经刷过一批题、希望提升独立解题能力的用户。

AI 更克制，更像面试官。它优先追问用户的思路、复杂度、边界条件和不变量，只在用户明确需要时给提示。

### 6.3 面试模拟模式

适合面试冲刺用户。

AI 以轻量 mock interview 的方式工作：控制时间节奏，追问题意理解、暴力解法、优化方向、复杂度、边界条件和代码实现。结束后给出面试表现复盘。

第一版只做算法题面试模拟，不扩展到系统设计、行为面试或简历辅导。

## 7. AI 教练边界

AI 教练必须遵守以下产品原则：

1. 默认不直接给完整答案。
2. 先理解用户当前思路，再决定是否提示。
3. 提示应分层递进，不能一步到位泄露完整解法。
4. 代码 review 优先定位问题和解释原因，不默认重写完整代码。
5. 复盘阶段可以解释完整思路，但重点仍是让用户理解推导过程。
6. AI 的每次帮助都应尽量沉淀为用户画像或下一步训练建议。

提示对用户展示为四个档位：

| 档位 | 产品含义 |
| --- | --- |
| 追问档 | 只提问和澄清，不提示题型或数据结构。 |
| 方向档 | 提醒题型方向或可能的数据结构，不给完整流程。 |
| 关键档 | 提醒核心不变量、关键步骤或伪代码框架。 |
| 复盘档 | 可以解释完整思路，但仍不默认贴完整提交代码。 |

## 8. 核心页面

### 8.1 登录、注册与 API 设置

提供本地账号能力，并允许用户保存自己的模型 API 资产。用户没有可用模型资产时，应先完成设置，再进入目标校准或 AI 教练流程。

### 8.2 目标校准页

采集用户目标、时间线、每周投入、默认训练语言和弱项。AI 根据这些信息生成可确认的学习计划。

### 8.3 学习计划页

展示当前 active 学习计划，包括阶段目标、训练重点、推荐题目、推荐理由和每道题状态。

用户可以从计划进入训练，也可以在后续版本中调整计划。

### 8.4 题库列表页

展示题目列表，支持按难度、标签、关键词和题单筛选。题库页是自由选题入口，学习计划页是主推荐入口。

### 8.5 做题工作台

承载核心训练过程：左侧展示题面，右侧提供 ChatGPT 式 AI 教练对话。用户在对话中描述思路、粘贴代码、接收 review，并在 LeetCode 提交后回填结果。

### 8.6 复盘页

展示本题结果、主要卡点、提示使用、错误类型、复杂度分析、画像变化和下一步建议。

### 8.7 学习仪表盘

展示用户的训练进展和能力画像，例如完成题数、题型掌握度、常见卡点、平均提示档位、独立完成比例和下一组推荐训练。

## 9. MVP 范围

### 9.1 第一版必须完成

- 本地用户注册登录。
- 用户级模型 API 资产配置。
- 题库导入、题库浏览和中文题面展示。
- 首访目标校准。
- AI 生成并由用户确认学习计划。
- 从学习计划进入做题工作台。
- 入门引导、独立训练和轻量面试模拟三种训练模式。
- AI 追问、分层提示和代码 review。
- AI 建议用户去 LeetCode 提交，并根据回填结果继续引导。
- 用户手动回填 LeetCode 提交结果。
- 单题复盘。
- 用户学习画像更新。
- 基础学习仪表盘。

### 9.2 第一版不做

- 不做完整在线判题系统。
- 不做本地代码运行或样例执行。
- 不抓取 LeetCode 隐藏测试用例。
- 不自动提交 LeetCode。
- 不把完整题解作为默认上下文喂给 AI。
- 不做复杂推荐算法，先用目标、题型、难度、历史卡点和计划阶段形成基础推荐。
- 不优先做排行榜、社区、分享、打卡提醒或移动端原生应用。
- 不扩展到系统设计、行为面试、简历润色等泛面试模块。
- 不在产品内维护多语言运行环境；用户的最终执行和提交以 LeetCode 为准。

## 10. 成功标准

第一版成功，不是指功能最多，而是指核心训练闭环成立：

- 新用户能完成目标校准，并得到一份可理解的学习计划。
- 用户能从学习计划进入一道题的完整训练过程。
- AI 能在不默认泄露完整答案的前提下，诊断卡点并推动用户继续思考。
- 用户能描述思路或粘贴代码，获得 AI review，并按建议去 LeetCode 提交后回填结果。
- 做完一题后，系统能生成复盘、更新画像并推荐下一步训练。

可量化观察指标：

- 完成目标校准的用户比例。
- 从学习计划进入第一题训练的比例。
- 单题训练完成率。
- 平均提示档位。
- 独立完成比例。
- 复盘查看率。
- 下一题继续训练比例。

## 11. 后续演进方向

第一版闭环跑通后，再逐步增强：

- 更稳定的 Agent 编排和可恢复训练状态。
- 更专业的教练知识库，让提示更像教练而不是题解。
- 更完善的 LeetCode 提交结果归因和错因总结。
- 更细的用户画像和个性化训练推荐。
- 更完整的面试模拟评分。
- 面向研发验证的 Trace、评估集和提示泄露检查。

这些能力都应服务一个主目标：让用户更少依赖答案，更多形成可迁移的独立解题能力。
