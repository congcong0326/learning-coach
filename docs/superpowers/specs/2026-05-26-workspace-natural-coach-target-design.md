## 3. 当前问题

当前工作台已经完成 Chat-first 和上下布局，但仍有两个体验断点。

第一，主界面保留“回填未通过结果”按钮和结构化弹窗。它把用户从自然聊天切回表单填写。实际 LeetCode 未通过时，用户最自然的行为是把平台提示、失败用例、报错和自己的判断直接粘给 AI，让 AI 判断下一步。表单入口会让产品显得像训练数据采集工具，而不是教练。

第二，点击“LeetCode 已 AC”后，复盘内容偏确定性统计，容易出现“提交/回填次数”“当前记录已进入 AC 复盘，但还没有稳定记录你的复杂度口述”这类系统视角文案。用户已经 AC 时，最期待的是教练根据本题历史对话、代码尝试、提示使用和画像，告诉他这题做得好在哪里、弱点在哪里、下一题该怎么练，而不是看到一份数据库事实摘要。

## 4. 产品目标

工作台目标体验应收敛为：

```text
用户在 LeetCode 做题
-> 在工作台读题和跟 AI 教练聊天
-> 用户自然粘贴思路、代码、失败提示或 AC 事实
-> AI 教练判断阶段、追问、提示、review 或归因
-> 用户点击“LeetCode 已 AC”
-> AI 基于本题完整训练历史生成教练式复盘
-> 复盘沉淀为画像和下一题建议
```

核心产品判断：

- 用户不需要为了“没通过”额外填写结构化表单。
- AC 是训练完成信号，不是普通聊天消息，也不是统计摘要触发器。
- 结构化训练事实仍然需要，但应由系统在后台从自然对话和明确动作中提取，不应强迫用户维护。
- 复盘必须是 AI 教练视角，重点是优点、缺点、证据和下一步训练，而不是内部状态翻译。

## 5. 方案选择

### 5.1 推荐方案：自然聊天 + 后台事实提取

移除主界面的“回填未通过结果”按钮和弹窗。用户遇到 WA、TLE、RE、CE 等情况时，直接在聊天框粘贴 LeetCode 返回内容、失败用例或自己的判断。

后端仍可保留 `submission_feedback` 表和 `submit_feedback` 语义，但它们不再是用户必须操作的主路径。系统可以在教练回合中识别“这是一条非 AC 提交反馈”，必要时把结果、失败用例和错误摘要沉淀为内部事实，用于后续归因、复盘和画像。

推荐原因：

- 用户路径最简单。
- 符合 Chat-first 产品方向。
- 不牺牲后端结构化能力。
- 可以渐进实现，不需要接入 LeetCode 官方 API。

### 5.2 备选方案：保留高级入口

保留“回填未通过结果”，但降级为隐藏在更多菜单或调试区域的高级入口。

优点是实现改动小，结构化数据最稳定；缺点是主路径仍然会暗示用户需要填写表单，产品气质不够自然。

### 5.3 暂不采用：自动接入 LeetCode 提交历史

通过浏览器插件、账号授权或爬取方式自动读取 LeetCode 提交结果。

这会显著增加账号、合规、稳定性和部署复杂度，偏离当前本地优先 MVP。第一版不做。

## 6. 目标用户体验

### 6.1 工作台主界面

工作台保留上下结构：

```text
题目标题和 LeetCode 原题入口
题面自然展开
AI 教练聊天区
```

教练区顶部只保留两个高频动作：

- 代码尝试记录。
- LeetCode 已 AC。

不再展示主路径按钮“回填未通过结果”。不再在主界面常驻“提交反馈历史”。失败结果如果已经被系统识别，可以作为教练回复中的上下文被使用，不需要单独占据界面。

聊天输入框 placeholder 应直接引导用户：

```text
粘贴你的思路、代码、LeetCode 报错或失败用例，教练会判断下一步
```

### 6.2 非 AC 结果体验

用户看到 LeetCode 未通过后，不需要找表单。推荐交互是直接发消息：

```text
这版 WA，失败用例是 nums=[3,3], target=6，输出是 []。
```

或：

```text
TLE 了，最后一个大用例超时。我现在是双重循环。
```

AI 教练应直接进入提交反馈分析：

- 判断这是 WA/TLE/RE/CE/MLE/Unknown 中哪类。
- 结合最近代码尝试和本轮文本定位可能问题。
- 给出下一步最小检查动作。
- 不要求用户重新填写结果。
- 不把失败反馈渲染成一条表单历史卡片。

如果信息不足，教练只问一个最关键补充问题，例如：

```text
我需要你补一个信息：LeetCode 显示的实际输出和期望输出分别是什么？
```

### 6.3 AC 后复盘体验

用户点击“LeetCode 已 AC”后，系统记录 AC 并自动生成复盘。复盘不是占位说明，也不是数据库字段摘要，而是教练对本题训练过程的总结。

复盘应至少包含：

- 本题最终结果：AC。
- 做得好的地方：基于历史对话和代码尝试提炼 1-3 点。
- 暴露的问题：基于提示使用、卡点、代码 review、失败反馈提炼 1-3 点。
- 关键能力判断：题意理解、方案推导、不变量、边界、复杂度、实现稳定性。
- 证据：引用经过摘要的训练事实，不贴完整用户输入或完整代码。
- 下一题训练策略：下一题先练什么、教练应如何起手。
- 画像变化：本题对长期画像的增量判断。

推荐结构：

```markdown
## 单题复盘

### 你做得好的地方
- ...

### 需要补强的地方
- ...

### 本题关键思路
- ...

### 下次遇到同类题
- ...

### 画像更新
- ...
```

如果历史证据不足，也要用教练口吻表达，而不是系统口吻：

```text
这题我能确认的是你已经完成 AC，但本轮对话里没有留下完整复杂度口述。下次同类题我会先让你用 30 秒说明状态维护和复杂度，再进入代码。
```

## 7. AI 教练行为目标

### 7.1 普通消息分类

用户普通发送仍使用自然语言输入。系统由模型和后端守卫共同判断本轮消息属于：

- 思路描述。
- 卡住求助。
- 请求提示。
- 代码 review。
- 非 AC 提交反馈。
- AC 或复盘请求。
- 其他追问。

用户不需要手动选择消息类型。

### 7.2 非 AC 归因

当用户文本包含 WA/TLE/RE/MLE/CE/Unknown、失败用例、错误信息或平台提示时，教练应优先做归因，而不是继续走基础追问。

后台可以把识别出的事实写成内部事件，例如：

```text
source = chat_extracted
result = wa
failed_case_summary = 有失败用例
error_summary = 有输出差异
```

这些字段只服务复盘、画像和 Trace 摘要，不在主聊天界面要求用户维护。

### 7.3 AC 复盘

`coach_summary` 应从确定性模板升级为模型驱动复盘。模型输入应包括：

- 题目信息和计划目标。
- 用户画像摘要。
- 本题聊天历史摘要。
- 最近代码尝试摘要和 AI 质量判断。
- 已识别的非 AC 反馈摘要。
- 提示档位、阶段轨迹和快进/回退信号。
- AC 事实。

模型输出必须是用户可读 Markdown，并遵守：

- 不贴完整提交代码。
- 不复述完整聊天原文。
- 不使用“回填”“事件”“阶段枚举”等内部词作为主要表达。
- 优先讲用户能力与下一步训练。
- 当证据不足时明确说明证据边界，并给下一次训练策略。

  - 新增或更新 `coach_summary` prompt，明确教练式复盘输出契约。

  - 覆盖 AC 后复盘包含“做得好的地方”和“需要补强的地方”。
  - 覆盖复盘不泄露完整代码和完整用户输入。

## 10. 数据与契约原则

保留内部结构化数据，但降低用户感知。

推荐语义：

- `submission_feedback.result = ac`：用户明确点击“LeetCode 已 AC”，用于完成本题。
- `submission_feedback.result != ac`：可以来自聊天识别、高级入口或未来自动接入，不再要求用户手动表单填写。
- `practice_event.content_md`：只展示真实用户消息和教练回复。
- `practice_event.payload_json`：只保存结构化摘要、结果类型和布尔标记；失败用例、错误信息等长文本仍放在受控业务字段中，进入 prompt、Trace 或日志前必须截断和脱敏。
- `agent_trace`：只记录截断摘要，不记录完整代码、完整用户输入或题解。

## 11. 非目标

本轮目标设计不包含：

- 不接入 LeetCode 官方账号、提交历史或自动提交。
- 不做站内判题、本地运行或样例执行。
- 不抓取隐藏测试用例。
- 不要求用户填写运行时间、内存、失败用例等表单字段。
- 不把完整聊天历史和完整代码直接塞入长期画像。
- 不改变“后端是 LLM 和训练事实边界，前端只调用后端 API”的架构原则。

## 12. 验收标准

产品验收：

- 工作台主界面不再出现“回填未通过结果”按钮。
- 用户可以把 WA/TLE/RE/CE/MLE 或失败用例直接发给教练。
- 教练能围绕用户粘贴的 LeetCode 失败信息做分析，而不是要求用户去填表。
- 点击“LeetCode 已 AC”后自动生成教练式复盘。
- 复盘包含“做得好的地方”和“需要补强的地方”。
- 复盘基于本题历史对话、代码尝试、提示使用和画像，不只是统计字段。
- 复盘不出现“回填次数”“当前记录已进入 AC 复盘”等系统视角主文案。
- 复盘能给出下一题训练策略和画像变化。

工程验收：

- 前端相关测试通过。
- 后端 `coach_turn`、`coach_summary` 和 practice service 相关测试通过。
- 复盘 Markdown 可以在聊天区正确渲染标题、列表和加粗。
- Trace 和日志不记录完整用户输入、完整代码或敏感信息。

## 14. 待审核决策

建议采用以下决策：

- 主界面完全移除“回填未通过结果”，不放到更多菜单。
- 非 AC 结果只通过聊天自然输入进入主路径。
