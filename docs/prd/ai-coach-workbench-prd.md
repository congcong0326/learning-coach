# PRD：单题 AI 教练工作台

## 1. 文档目的

本文档定义当前 MVP 的做题工作台产品行为。它不定义数据库表、API 路径、Prompt 模板或具体实现。

## 2. 产品定位

工作台是用户完成单题训练的主界面。它不是在线判题系统，也不是题解展示页，而是围绕一道题维护训练上下文，让 AI 教练根据用户输入持续诊断、提示、review 和复盘。

## 3. 入口与身份

当前主入口是学习计划项：

- 用户从当前学习计划进入 `/workspace/items/:itemId`。
- 后端为该计划项创建或恢复同一个训练会话。
- 训练会话绑定用户、题目、计划项和 thread id。

兼容入口：

- `/workspace` 可以作为工作台空态或恢复入口。
- `/workspace/:slug` 可以作为题库自由选题入口。

计划版本变化不应破坏已有训练会话。工作台优先使用会话创建时的计划题上下文；需要展示最新计划信息时，作为辅助上下文处理。

## 4. 页面布局

当前工作台应包含：

- 题面区：展示题目标题、难度、标签、中文题面和 LeetCode 原题入口。
- 代码区：用户可粘贴或编辑代码片段，用于发给教练 review。
- 教练区：Chat-first 对话、流式回复、阶段状态、提示档位、提交反馈和 AC 动作。
- 代码尝试抽屉或列表：展示从聊天中提取或用户提交过的代码尝试。

不应出现：

- 默认展示完整题解。
- 在低提示档位直接给可提交代码。
- 将 LeetCode 未通过结果拆成繁重表单，阻断用户自然粘贴反馈。
- 把本地运行结果伪装成 LeetCode 官方结果。

## 5. 标准训练流程

```text
进入工作台
-> 用户描述理解、思路、卡点或代码
-> AI 判断当前阶段和卡点
-> AI 追问或给分层提示
-> 用户补充思路或代码
-> AI review 代码或建议去 LeetCode 提交
-> 用户粘贴非 AC 反馈，或点击“LeetCode 已 AC”
-> 非 AC 继续归因和引导
-> AC 后生成单题复盘
```

## 6. 教练状态

当前产品层状态可以抽象为：

| 状态 | 含义 |
| --- | --- |
| `understand_problem` | 确认题意、输入输出、约束和边界。 |
| `explore_bruteforce` | 引导用户说出暴力解法和复杂度。 |
| `optimize_approach` | 引导用户识别可优化结构、状态或不变量。 |
| `review_code` | 基于用户代码定位实现问题。 |
| `analyze_submission` | 分析 LeetCode 非 AC 反馈。 |
| `summarize` | AC 后复盘。 |

LLM 可以提出阶段判断，但后端必须守卫关键跳转：

- 没有用户思路或代码时，不能直接进入完整解法。
- 没有代码时，不能执行代码 review。
- 没有 AC 事实时，不能生成终态复盘。
- 低提示档位不能输出完整可提交答案。

## 7. 用户输入与动作

用户输入可以是：

- 自然语言思路。
- 卡点描述。
- 代码片段或完整代码。
- LeetCode 非 AC 反馈，如 WA、TLE、RE、MLE、CE 或 UNKNOWN。
- AC 确认动作。

业务动作包括：

- 发送教练消息。
- 保存代码快照。
- 记录提交反馈。
- 标记 LeetCode 已 AC。
- 请求单题复盘。

非 AC 结果的主路径是聊天输入。系统应从用户消息中提取必要事实，并把提取结果作为提交反馈进入后续上下文。

## 8. 提示档位

| 档位 | 允许内容 | 禁止内容 |
| --- | --- | --- |
| 追问档 | 澄清题意、询问用户当前想法、提醒先写暴力 | 直接说题型、给关键不变量、贴代码 |
| 方向档 | 提醒可能的数据结构或题型方向 | 给完整流程或可提交代码 |
| 关键档 | 给关键不变量、核心步骤、伪代码框架 | 默认重写完整答案 |
| 复盘档 | 解释完整思路、复杂度和常见坑 | 把复盘变成无上下文的题解粘贴 |

提示档位可以随训练推进升高，但必须有用户请求、连续卡住、提交失败或复盘阶段等证据。

## 9. 代码 Review

AI review 代码时应优先回答：

- 主要问题类型是什么。
- 大致发生在哪个逻辑区域。
- 为什么会导致错误。
- 用户应该优先检查哪个输入、状态或边界。

AI 不应默认重写整段可提交代码。需要代码示例时，应遵守用户目标校准中的默认训练语言。

## 10. LeetCode 反馈

当前 MVP 以 LeetCode 官网为最终运行和提交来源。

AC：

- 只能由明确“LeetCode 已 AC”动作或等价 AC 提交反馈确认。
- AC 后可以生成复盘、画像增量和下一题建议。

非 AC：

- 用户可直接把失败信息粘贴到聊天框。
- 系统识别状态、错误摘要和必要上下文。
- AI 根据反馈引导定位，不伪造隐藏测试用例。

## 11. 复盘沉淀

单题复盘应包含：

- 本题最终结果。
- 用户主要卡点。
- 使用过的最高提示档位。
- 代码错误类型。
- 时间复杂度和空间复杂度。
- 本题真正需要掌握的核心思路。
- 对用户学习画像的更新。
- 下一题或下一组训练建议。

复盘阶段允许解释完整思路，但重点是把训练事实转化为可执行改进建议。

## 12. MVP 范围

当前必须完成：

- 计划题进入工作台并创建/恢复训练会话。
- 题面展示、代码输入、Chat-first 教练区。
- 流式 AI 回复。
- 分层提示和阶段守卫。
- 代码尝试记录。
- 聊天式非 AC 反馈识别。
- LeetCode 已 AC 动作。
- 单题复盘读取和展示。

当前可以简化：

- 教练状态可以先用有限状态和规则守卫实现。
- 下一题建议可以先用计划顺序、难度和近期弱项规则实现。
- 画像展示可以先聚焦复盘证据，不做完整仪表盘。

当前不做：

- 本地代码执行。
- 自动提交 LeetCode。
- Trace 页面。
- RAG 检索。
- 学习计划历史/版本切换 UI。
- 面试模拟独立入口。

## 13. 成功标准

- 用户从学习计划进入工作台后，可以围绕同一道题持续对话且刷新后恢复。
- AI 默认不泄露完整答案，低提示档位守卫有效。
- 用户粘贴非 AC 反馈后，AI 能进入提交反馈分析而不是泛泛安慰。
- 用户 AC 后能看到与本次训练事实相关的复盘和下一题建议。
- 关键行为有后端测试、前端测试和 eval 覆盖。
