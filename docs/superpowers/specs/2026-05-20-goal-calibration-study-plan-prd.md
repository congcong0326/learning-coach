- 用户已经具备本地账号和用户级 LLM API 资产。

- 计划调整由用户手动触发，用户确认后克隆生成新版本。

## 背景与问题

现有 PRD 已经把「目标校准 -> 训练计划 -> 选题 -> 做题 -> 复盘画像 -> 下一组训练」定义为第一版闭环。但早期 T1 设计更偏工程可落地的规则推荐，只能解决「生成一组题」的问题，无法支撑后续长期学习路径。

用户真实需求不是拿到一个静态题单，而是：

- 把模糊目标转成可执行路径。
- 根据当前水平、时间投入和目标压力决定训练节奏。
- 在训练过程中保留历史计划，同时只围绕一个当前计划训练。
- 当目标或水平变化时，可以解释性地调整计划。
- 让计划和后续训练记录、提交历史、复盘画像形成可追溯关系。

因此，T1 需要从「规则生成题单」升级为「LLM 辅助目标校准和版本化学习计划管理」。

## 产品目标

本需求的目标是：让用户通过一次目标校准，生成一个可以被激活、暂停、版本化调整，并能持续关联训练记录的阶段化学习计划。

用户价值：

- 新用户可以通过结构化表单和 LLM 追问，把模糊目标转成可执行训练路径。
- 老用户可以基于已有训练历史、提交结果、提示使用、卡点和画像，生成更贴合当前水平的计划。
- 用户可以拥有多个学习计划，例如「面试冲刺计划」「动态规划专项计划」「保持手感计划」。
- 任意时刻只有一个 active 计划，避免 AI Coach 上下文和训练归因混乱。
- 激活某个计划时，该计划自带的目标快照也成为当前训练上下文。
- 用户可以手动触发计划调整，系统说明为什么调整、调整了什么、预期解决什么问题。

## 产品方案

采用「MVP 计划管理器」方案。

核心特征：

- 多计划管理：用户可以拥有多个计划，任意时刻只有一个 active。
- 目标快照：每个计划自带目标、投入、弱项、默认语言和训练偏好。
- 阶段化计划：计划包含完整阶段框架，但只细化当前阶段题单。
- LLM 规划：LLM 先根据用户状态生成阶段和题目建议。
- 后端校验：正式计划项必须来自本地题库，并通过状态、难度、重复和付费校验。
- 版本化调整：调整计划时克隆当前版本，用户确认后新版本生效。
- 用户受控编辑：用户可以表达偏好和请求替换题目，但不能绕过校验。

不采用以下方案：

- 不做主动教练型计划系统：第一版不在阶段完成、连续失败或画像变化时自动打扰用户调整计划。
- 不做自由计划编辑器：第一版不允许用户绕过题库和状态约束自由改正式计划结构。

## 核心流程

```text
用户进入目标校准
  -> 填写结构化表单
  -> LLM 根据缺口追问 1-3 个问题
  -> LLM 生成目标理解和阶段化计划草稿
  -> 后端用本地题库校验题目、题型、难度和重复项
  -> 如校验失败，进入有限轮次 repair loop
  -> 用户查看草稿并做受控编辑
  -> 用户确认
  -> 创建学习计划 v1 并激活
  -> 用户按当前阶段详细题单训练
  -> 用户手动触发调整计划
  -> 系统基于训练历史生成调整建议
  -> 用户确认
  -> 克隆生成学习计划新版本并激活
```

## 目标校准输入

目标校准分为结构化采集和 LLM 补问两段。产品上不做纯聊天入口，避免目标校准变成不可控长对话。

结构化表单字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 学习目标 | 单选 | 刷题入门、面试冲刺、专项补弱、保持手感。 |
| 时间线 | 单选 | 无明确时间、1 个月内、1 到 3 个月、3 个月以上。 |
| 每周投入 | 数字 | 每周可训练天数。 |
| 单次时长 | 数字 | 单次训练时长。 |
| 当前水平 | 单选 | 没系统刷过、做过少量 Easy、能做部分 Medium、刷过一轮但不稳定。 |
| 默认训练语言 | 单选 | C、Go、Python3、JavaScript、Java。 |
| 自评弱项 | 多选 | 题意理解、题型识别、复杂度优化、代码实现、边界条件、面试表达。 |
| 目标补充说明 | 文本 | 目标公司、面试时间、最怕的题型、希望训练风格等。 |
| 训练偏好 | 单选 | 更希望被引导、先独立思考再提示、偏面试官追问。 |

默认训练语言用于：

- 工作台默认语言。
- 代码模板默认语言。
- AI code review 的语言上下文。
- 后续代码运行工具选择。

产品层面声明支持 C、Go、Python3、JavaScript 和 Java；各语言 code-runner 的分阶段实现由后续研发计划拆分。

## LLM 追问机制

LLM 最多追问 1 到 3 个问题。只追问会显著影响计划的问题。

典型追问场景：

- 用户选择面试冲刺，但没有面试时间或目标公司信息。
- 用户选择专项补弱，但没有明确弱项。
- 用户每周投入很少，但目标周期很短。
- 用户自由文本描述和结构化选项冲突。
- 用户历史训练记录显示的弱项和自评弱项冲突。

追问规则：

- 每次只展示一个问题。
- 用户可以回答，也可以跳过剩余追问。
- 跳过追问后，系统仍可生成计划，但草稿中必须标记不确定性。
- 不追问无关细节，不做开放式长访谈。
- 追问记录保存到目标校准草稿中，用于解释计划生成依据。

追问结束后，系统生成：

- 目标理解摘要。
- 目标快照。
- 计划生成依据。
- 完整阶段框架。
- 当前阶段详细题单。
- 计划质量提示。
- 不确定性提示。

## 用户状态来源

计划生成使用「用户自评 + 系统已有训练历史」。

新用户主要依赖：

- 结构化表单。
- LLM 追问回答。
- 用户自由文本说明。

老用户额外结合：

- 已完成题目。
- 提交结果。
- 提示使用情况。
- 常见卡点。
- 复盘摘要。
- 用户画像。

如果用户自评和系统画像冲突，计划草稿必须显式说明冲突。例如：「你自评主要弱在动态规划，但最近训练记录显示边界条件错误更频繁，因此当前阶段会保留边界条件专项训练。」

## 学习计划结构

学习计划不是单层题单，而是「目标快照 + 阶段框架 + 当前阶段详细任务 + 版本记录」。

学习计划包含：

- 计划名称：例如「3 个月 Java 面试冲刺计划」。
- 目标快照：生成计划时用户确认的目标、时间线、投入、弱项、默认训练语言和训练偏好。
- 计划状态：`active`、`paused`、`archived`、`completed`。
- 当前版本：例如 `v1`、`v2`。
- 阶段列表：每个阶段有阶段目标、训练重点、建议题型、验收标准。
- 当前阶段详细任务：当前阶段下的具体题目、训练模式、推荐理由、状态和顺序。
- 后续阶段概览：后续阶段只保存方向，不强制生成完整题单。
- 生成说明：为什么生成这份计划，使用了哪些用户信息和训练证据。
- 调整说明：每次版本变化时记录原因、变更内容和预期收益。

## 多计划规则

- 用户可以拥有多个学习计划。
- 任意时刻只能有一个 `active` 计划。
- 激活某个计划时，其他 active 计划自动变为 `paused`。
- 历史计划只支持查看和重新激活。
- 非 active 计划不能直接继续训练。
- 重新激活历史计划时，该计划的目标快照成为当前训练上下文。
- `archived` 计划只读，不支持重新激活，除非后续产品另行开放。

## 学习计划版本规则

- 初次确认计划生成 `v1`。
- 用户手动触发「调整计划」后，系统基于当前 active 计划克隆生成新版本草稿。
- 用户确认调整后，新版本成为当前版本。
- 旧版本保留，只读展示。
- 新版本可以新增题目，也可以移除旧版本中未开始的题目。
- 已经做过、有训练记录或提交历史的题目不能从新版本中删除。
- 计划调整必须说明触发原因、使用证据、变更内容和预期收益。

计划项状态：

| 状态 | 说明 |
| --- | --- |
| `pending` | 未开始。 |
| `in_progress` | 训练中。 |
| `completed` | 已完成。 |
| `skipped` | 用户跳过。 |
| `locked_completed` | 历史已完成项，在新版本中保留且不可删除。 |

## LLM 计划生成

LLM 负责：

- 理解用户目标、时间线、投入和当前水平。
- 结合训练历史总结用户当前能力状态。
- 设计完整阶段框架，例如基础补齐、模式训练、综合训练、面试模拟。
- 为当前阶段推荐具体 LeetCode 题目、题型、难度和训练顺序。
- 给出每道题的推荐理由、建议训练模式和阶段验收标准。
- 生成面向用户可读的计划说明。

LLM 计划生成默认使用简体中文语境。计划名称、阶段标题、阶段目标、验收标准、生成说明、不确定性提示和推荐理由等面向用户展示的文本必须使用简体中文；`problem_slug`、难度、训练模式、标签 slug、枚举值、URL、代码语言名称和目标快照中的原始机器值保留英文或原始值。

LLM 输出必须是结构化草稿，不能直接写入正式计划。

## 后端题库校验

后端负责：

- 校验推荐题目是否存在于本地题库。
- 校验题目是否为付费题，第一版默认排除 paid only。
- 校验重复题目、题目 slug、题号和标题匹配。
- 校验当前阶段题单数量是否满足范围。
- 校验难度节奏是否符合用户当前水平和时间线。
- 校验已完成题目不能在新版本中被删除。
- 对 LLM 输出做 schema 校验，避免自由文本污染正式计划。

最终展示给用户的计划草稿中，正式题目必须全部引用本地题库中存在且可训练的题目。

## Repair Loop

如果 LLM 推荐的题目不存在、付费、重复或与题型明显不匹配，后端返回校验失败原因，系统进入 repair loop。

repair loop 规则：

- 最多执行 2 到 3 轮。
- 优先让 LLM 根据失败原因给出替代题。
- 如果仍失败，后端可以按题型、难度和分类从本地题库中补位。
- 如果某个题型在本地题库中没有合适题目，计划中保留题型目标，但当前阶段题单不引用不存在的题。
- repair 结果需要在草稿中说明。

用户可见示例：

```text
原建议题目 "X" 未在本地题库中找到，已替换为 "Y"。
替换后仍训练双指针窗口收缩能力，难度保持 Medium。
```

失败处理：

- LLM 调用失败时，用户可以重试，草稿不落库为正式计划。
- repair 后仍没有足够题目时，允许生成较短计划，但必须提示题库覆盖不足。
- 本地题库为空时，阻止生成正式计划，提示先导入题库。
- 用户没有可用 LLM API 资产时，引导用户去 API 设置页配置。

## 计划调整流程

计划调整只由用户手动触发。系统不在每题复盘后自动弹出调整建议，也不在阶段节点主动打扰用户。

调整入口：

- 学习计划页提供「调整计划」入口。
- 用户选择调整原因并补充说明。

调整原因包括：

- 时间投入变化。
- 面试时间变化。
- 当前计划太难。
- 当前计划太简单。
- 想加强某类题型。
- 想减少某类题型。
- 想切换默认训练语言。
- 其他补充说明。

调整生成流程：

```text
用户点击调整计划
  -> 填写调整原因和补充说明
  -> 系统读取当前 active 计划、当前版本、训练历史、提交历史和画像
  -> LLM 生成调整建议草稿
  -> 后端校验题库、状态和不可删除项
  -> 如失败进入 repair loop
  -> 用户查看调整建议
  -> 用户确认
  -> 克隆当前计划生成新版本
  -> 新版本成为当前 active 版本
```

调整后的新版本规则：

- 新版本从当前版本克隆而来。
- 已完成或已有记录的计划项必须保留。
- 未开始题目可以被移除、替换或重排。
- 新增题目必须来自本地题库。
- 版本必须记录变更说明。

变更说明包含：

- 调整前问题。
- 使用的证据。
- 新增题目列表。
- 移除题目列表。
- 保留但位置变化的题目。
- 训练强度或阶段目标变化。
- 预期收益。

## 用户受控编辑

用户可以在计划草稿或调整草稿中做以下操作：

- 修改目标描述和补充说明。
- 调整训练强度，例如题量更少、节奏更慢、难度更稳。
- 指定想加强的题型。
- 指定想减少或暂时避开的题型。
- 请求替换某道未开始题目。
- 调整当前阶段未开始题目的顺序。
- 修改默认训练语言。
- 修改训练偏好，例如更引导或更独立。

用户不能直接做以下操作：

- 删除已经完成的题目。
- 删除已有训练记录、提交历史或复盘记录的题目。
- 添加本地题库不存在的题目作为正式计划项。
- 把 paid only 题目加入第一版正式计划。
- 绕过后端校验直接保存 LLM 原始输出。
- 修改历史版本内容。

## 页面与交互

### 目标校准页

功能：

- 展示结构化表单。
- 表单提交后进入 LLM 追问区。
- 追问区以短问题形式展示，每次最多一个问题。
- 用户可以回答，也可以跳过剩余追问。
- 追问完成后进入生成中状态。
- 生成完成后展示计划草稿。
- 草稿展示目标理解、阶段框架、当前阶段题单、校验/替换说明和不确定性提示。
- 用户可以重试生成、受控编辑或确认创建计划。

### 学习计划页

功能：

- 默认展示当前 active 计划。
- 顶部展示计划名称、状态、当前版本、默认语言、目标摘要和计划周期。
- 展示当前阶段进度：已完成、进行中、未开始、跳过。
- 展示阶段列表。
- 当前阶段展开显示详细题单。
- 后续阶段显示阶段目标、题型方向和验收标准，不显示完整题单。
- 题单项展示题号、标题、难度、标签、建议训练模式、推荐理由、状态。
- 每个未开始题目支持进入工作台、跳过、替换建议、上移和下移。
- 已完成题目只读展示，可查看训练记录和提交历史。
- 页面提供「调整计划」入口。

### 计划列表/历史页

功能：

- 展示用户所有学习计划。
- 区分 active、paused、completed、archived。
- 支持查看历史计划详情。
- 支持重新激活 paused 或 completed 计划。
- 重新激活前展示确认：激活后其他计划会暂停，当前训练上下文会切换到该计划目标快照。
- archived 计划只读。

### 计划版本详情

功能：

- 在计划页展示当前版本号。
- 用户可以打开版本历史。
- 版本历史展示版本号、创建时间、调整原因、新增题目、移除题目、保留项和训练强度变化。
- 历史版本只读。

### 工作台入口

规则：

- 用户只能从 active 计划的计划项进入绑定计划的训练。
- 从非 active 计划进入时，提示先激活该计划。
- 直接从题库进入工作台时，不绑定计划。
- 如果题库题目属于当前 active 计划，可以提示关联到对应计划项。
- 工作台需要读取 active 计划目标快照，用于后续 AI Coach 上下文。

## 核心产品对象

| 对象 | 用途 |
| --- | --- |
| `Goal Calibration Draft` | 保存表单输入、LLM 追问记录、生成草稿、校验结果和失败原因。 |
| `Study Plan` | 学习计划容器，保存计划名称、状态、当前版本、目标快照和激活关系。 |
| `Study Plan Version` | 保存阶段框架、当前阶段题单、生成说明、调整说明和版本号。 |
| `Study Plan Stage` | 保存阶段目标、训练重点、建议题型、验收标准和阶段状态。 |
| `Study Plan Item` | 关联本地题库题目，保存推荐理由、建议训练模式、状态、顺序和是否锁定。 |
| `Plan Change Log` | 保存新增、移除、保留、替换和重排说明。 |
| `Practice Session / Submission History` | 训练记录和提交历史，产品上必须能关联到计划、计划版本和计划项。 |

训练记录和提交历史在新版本中的深拷贝或浅拷贝语义由后续研发设计决定。产品层只要求可追溯、不可丢失，并且已完成或已有记录的题目不能被新版本删除。

## 非目标

- 不做日历、打卡提醒、每日任务推送。
- 不自动触发计划调整。
- 不允许非 active 计划直接继续训练。
- 不把 LLM 未校验输出直接保存为正式计划。
- 不要求首次生成完整周期内所有题目的详细清单。
- 不在产品层面决定训练历史对新版本是深拷贝还是浅拷贝，只定义必须可追溯。
- 不做社交、排行榜、组织空间或团队计划。
- 不在 T1 产品设计中实现完整在线判题系统。

## 验收标准

- 用户可以通过结构化表单和最多 3 个 LLM 追问生成计划草稿。
- 计划草稿必须包含目标理解、目标快照、完整阶段框架、当前阶段详细题单和验收标准。
- 当前阶段题单中的正式题目必须全部来自本地题库，并通过后端校验。
- 题目缺失、付费、重复或不匹配时，系统能进入有限 repair loop 并给出替换说明。
- 用户确认后创建学习计划 `v1`，并将其设为唯一 active 计划。
- 用户可以拥有多个计划，但同一时间只能有一个 active。
- 用户可以查看历史计划并重新激活 paused 或 completed 计划。
- 用户手动触发调整后，系统生成新版本草稿，用户确认后才生效。
- 新版本不能删除已完成、已有训练记录或已有提交历史的题目。
- 每次计划调整都有用户可见的原因、证据、变更和预期收益说明。
- active 计划的目标快照能作为工作台和后续 AI Coach 的上下文来源。
- 非 active 计划项不能直接进入训练，必须先激活计划。
