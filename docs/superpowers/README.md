# Superpowers 设计入口

本目录只保存后续新增大功能或重要架构决策的当前版本设计。

本轮重构前的历史规格和实施计划已经删除，因为它们记录的是早期探索、已完成任务或已回退能力，不再代表当前代码能力。需要恢复 RAG、Trace、备份恢复、code-runner、学习仪表盘、画像驱动计划补强或学习计划历史 UI 时，必须先在这里新增当前版本设计。

## 新文档命名

建议命名：

```text
YYYY-MM-DD-feature-design.md
```

如果一个功能确实需要实施计划，可在同一文档内增加“实施步骤”章节。除非任务很大，不再默认拆分 `specs/` 和 `plans/` 两套文件。

## 推荐结构

新设计至少包含：

- 背景和目标。
- 当前代码事实。
- 范围内和范围外。
- 产品或工程边界。
- 涉及文件和模块。
- 数据、API、前端和 Docker 影响。
- 风险和安全约束。
- 验收标准。
- 验证命令。
- 文档维护影响。

## 维护规则

- 新设计必须以 `docs/index.md`、`docs/prd/prd.md`、`docs/architecture/foundation.md` 和实际代码为基础。
- 如果设计与当前文档冲突，先明确是修改设计、修改文档，还是同时调整。
- 功能完成后，如果设计只剩历史价值，应删除或重写为当前行为说明，不长期保留过期计划。
