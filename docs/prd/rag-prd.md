# RAG PRD v0.2：教练知识库与知识增强

文档状态：已认可，作为 T6/RAG 工程设计和实施计划的产品依据。

## 1. 文档目的

本文档定义 Agentic Coding Learning Coach 中 RAG 的产品需求：RAG 要为谁解决什么问题、怎样影响 AI 教练行为、第一阶段做什么、不做什么，以及如何验收。

本文档不展开数据库表、embedding 模型、切块算法、LangGraph 节点实现或导入脚本细节。工程设计和实施计划应在本文档确认后另行拆分；候选材料清单以 `docs/prd/rag-materials.md` 为准。

## 2. 当前产品决策

- 轻量面试模拟模式已从第一版 MVP 降级为后续探索。当前主线优先做常规刷题训练闭环和 RAG 教练知识增强。
- RAG 第一阶段只服务做题工作台的 AI 教练，不优先接入目标校准、计划生成或通用资料搜索。
- RAG 的产品形态不是“用户查资料”，而是“后端给 AI 教练提供可过滤、可追踪、可控泄露程度的教练知识”。
- RAG 不能绕过训练状态机、提示档位和 `coach_guard`。检索命中完整题解时，低提示档位仍必须过滤或降级使用。

## 3. 产品定位

RAG 在本项目中不是通用搜索，也不是把完整题解塞进模型上下文。

RAG 的产品定位是：把本地整理的算法教程、题型路线、常见错误、提示策略和面试表达材料，转化为可过滤、可追踪、可约束泄露程度的“教练知识”，用于让 AI 教练更稳定地完成诊断、追问、分层提示、代码 review、提交反馈分析和单题复盘。

它必须服务主产品目标：让用户更少依赖答案，更多形成可迁移的独立解题能力。

## 4. 为什么现在需要 RAG

当前非 RAG AI 教练已经能基于题面、用户输入、学习计划、训练事件和画像进行对话。但只依赖模型参数和当前上下文，会产生几个产品问题：

- 同一题型的追问和提示结构不稳定，有时过早泄露完整思路，有时又追问过多。
- 题型知识缺少统一表达，例如滑动窗口、双指针、动态规划、图搜索等题型的识别信号、关键不变量和常见错误。
- 代码 review 容易泛泛而谈，不能稳定说明是哪类边界、哪类状态维护或哪类复杂度问题。
- 提交失败分析依赖模型临场发挥，WA/TLE/RE 等结果缺少稳定的调试检查清单。
- 复盘质量不稳定，用户做完题后不一定能沉淀“下次如何识别同类题、如何避免同类错误”。

RAG 的价值是给 AI 教练提供外部、稳定、可审计的训练知识来源，同时继续让后端守卫控制提示档位和泄题边界。

## 5. 目标效果

### 5.1 P0：提升做题工作台教练质量

第一阶段 RAG 只面向做题工作台。用户应该感受到：

- AI 更像教练，而不是题解生成器。
- AI 对同一类题的追问、提示和复盘有稳定结构。
- AI 能围绕题型知识卡片追问关键不变量、边界条件和复杂度来源。
- AI 代码 review 能结合常见 bug 卡片指出问题类型、影响范围和优先检查输入。
- AI 分析非 AC 反馈时能给出更具体的调试方向，而不是只说“检查边界”。
- AI 复盘能沉淀题型识别信号、关键思路、常见误区和下一题训练建议。

### 5.2 P1：辅助计划补强和计划调整

第二阶段 RAG 再服务学习计划相关能力。用户应该感受到：

- 补强题不只是按难度追加，而是围绕题型路线、材料路线和用户弱项组织。
- 推荐理由能说明当前阶段为什么练这些题型、这些题之间是什么递进关系。
- 计划调整能结合近期复盘和画像弱项，补充对应题型材料、练习顺序和复盘重点。

### 5.3 P2：支持更完整评估和长期训练

后续 RAG 还要服务 Agent 工程质量：

- 每次检索都可追踪，能看到 query 摘要、过滤条件、命中片段、被过滤原因和最终注入上下文。
- RAG Grounding Eval 能验证回复是否基于允许召回的材料。
- Hint Leakage Eval 能验证低提示档位不会因为检索命中完整题解而泄题。

## 6. P0 用户场景

| 场景 | 检索意图 | 预期教练行为 | 不允许行为 |
| --- | --- | --- | --- |
| 用户说看不懂题 | `concept_explain`、`problem_understanding` | 召回概念澄清、题意拆解和引导问题 | 直接给题型答案或完整解法 |
| 用户不知道怎么开始 | `pattern_direction` | 召回题型识别信号、暴力到优化的思考方向 | 直接列出完整算法步骤 |
| 用户请求提示 | `hint_progression` | 按当前提示档位召回可用 hint，逐层推进 | 跳过档位给复盘级答案 |
| 用户粘贴代码 | `code_review` | 召回 common bug、不变量和语言注意点，定位问题类型和检查方向 | 替用户重写整段可提交代码 |
| 用户粘贴 WA/TLE/RE/MLE/CE | `submission_feedback` | 召回错误类型相关调试清单和常见归因 | 无证据断言唯一错因 |
| 用户 AC 后复盘 | `session_summary` | 召回题型总结、关键思路、复杂度、常见误区和下一题建议 | 大段搬运原文或把复盘变成题解粘贴 |

## 7. 知识来源与知识形态

### 7.1 候选材料

候选材料来自 `docs/prd/rag-materials.md`。第一批优先考虑：

- 代码随想录。
- labuladong 的算法笔记。
- Hello 算法。
- LeetCode 101。
- NeetCode Roadmap / NeetCode 150。
- AlgoMonster 或 Grokking the Coding Interview。

材料必须由用户本地整理或具备可使用授权。系统只负责解析、清洗、切块、抽取卡片和记录来源，不负责绕过版权、付费墙或平台限制。

### 7.2 不直接检索完整原文

第一阶段不把整篇教程、完整章节或完整题解作为默认 RAG 输入。优先使用面向教练场景的派生卡片。

| 卡片类型 | 产品用途 |
| --- | --- |
| `concept_card` | 解释基础概念、术语、复杂度和数据结构特性。 |
| `pattern_card` | 描述题型模式、识别信号、适用条件和推导方向。 |
| `invariant_card` | 描述解法成立所依赖的不变量、状态定义或维护规则。 |
| `common_bug_card` | 描述常见实现错误、边界遗漏、复杂度误判和调试方向。 |
| `hint_card` | 提供分层提示，必须标注适用提示档位。 |
| `problem_coach_card` | 面向单题的教练视角，说明训练重点和追问方向，不等同于完整题解。 |
| `interview_expression_card` | 帮助用户在复盘阶段组织复杂度解释和表达话术。 |
| `plan_path_card` | 描述题型路线、阶段目标、题单关系和先后依赖，用于后续计划设计。 |

### 7.3 第一阶段入库形态

P0 不要求一开始完成全自动高质量抽卡。允许先支持两条入库路径：

- 人工整理或半自动生成的教练卡片文件，适合快速验证产品效果。
- Markdown/txt 材料导入后进行章节解析、清洗和切块，再逐步派生教练卡片。

第一阶段的验收重点是“AI 教练行为是否变稳定”，不是“抽卡自动化程度有多高”。

## 8. 必要元数据

每个知识卡片或 chunk 至少需要支持以下元数据：

| 字段 | 产品用途 |
| --- | --- |
| `source_name` / `source_url` / `source_locator` | 追踪知识来源和章节位置。 |
| `license_note` | 记录材料使用说明或授权备注，避免误用受限材料。 |
| `knowledge_type` | 区分概念、题型、bug、提示、表达、路线等知识。 |
| `problem_slug` / `problem_tags` | 支持按当前题目和题型召回。 |
| `difficulty` | 支持计划设计和提示难度控制。 |
| `phase` | 匹配理解题意、推导方案、写代码、review、提交反馈、复盘等阶段。 |
| `stuck_point` | 匹配用户当前卡点，例如不变量不清、边界遗漏、复杂度错误。 |
| `hint_level_min` / `hint_level_max` | 控制知识可在哪些提示档位出现。 |
| `has_full_solution` | 防止低提示档位召回完整解法、完整伪代码或可提交代码。 |
| `language` | 支持中文教练回复和后续多语言训练材料。 |
| `quality_score` | 支持过滤低质量或抽取不稳定的卡片。 |

## 9. 提示档位边界

RAG 必须遵守当前 AI 教练提示档位。检索命中不能改变用户当前可获得的提示上限。

| 档位 | 允许召回 | 禁止召回 |
| --- | --- | --- |
| 追问档 | 概念澄清、题型识别信号、引导问题、无答案导向的检查清单 | 题型答案、完整流程、伪代码、可提交代码 |
| 方向档 | 题型方向、可能数据结构、暴力到优化的思考方向 | 完整算法步骤、关键状态转移全量展开、完整代码 |
| 关键档 | 关键不变量、核心步骤、局部伪代码框架、常见 bug | 直接可提交的完整解法代码 |
| 复盘档 | 完整思路解释、复杂度分析、题型总结、面试表达 | 与用户训练无关的大段原文搬运 |

如果知识片段同时满足多个档位，按最低安全档位使用。如果片段含完整解法风险，必须标记 `has_full_solution=true`，低提示档位不能注入。

## 10. 检索与注入规则

### 10.1 上下文优先级

教练上下文优先级应保持与工作台 PRD 一致：

1. 当前题面和约束。
2. 当前学习计划、阶段目标和计划项推荐理由。
3. 用户长期画像。
4. 最近单题复盘摘要和画像增量。
5. 当前用户输入、最近关键事件、最新代码或提交反馈。
6. RAG 教练知识卡片。

RAG 片段不能挤掉当前题面、用户输入、代码证据和提交反馈。

### 10.2 上下文预算

- 第一阶段每轮最多注入 3 到 5 个知识片段。
- 注入内容应是摘要化后的教练知识，不注入大段原文。
- 代码 review 和提交反馈分析中，RAG 只能辅助归因，不能替代用户代码和 LeetCode 结果证据。
- 如果没有高质量命中，系统应回退到非 RAG 教练流程，而不是强行注入低相关材料。

### 10.3 用户可见表达

第一阶段不做独立资料搜索页，也不要求用户在工作台里看到完整引用面板。

AI 回复可以自然吸收教练知识，但不应在低提示档位说“资料里的完整解法是”。如果需要说明依据，应使用简短表达，例如“这类题通常先检查状态维护和边界用例”，而不是暴露大段来源原文。

## 11. Trace 与评估要求

RAG 必须可观测，否则很难判断模型是否真的受材料约束。

Trace 中至少需要记录：

- query 摘要。
- 检索意图。
- 当前提示档位。
- 过滤条件。
- 命中片段 ID。
- 被过滤片段 ID 和原因。
- 最终注入片段 ID。
- 是否注入 prompt。

不得记录完整用户输入、完整用户代码、API key、session token、完整题解或大段原文。

Eval 至少覆盖：

- 低提示档位命中完整题解时仍不泄题。
- 方向档只能给题型方向，不能给完整算法步骤。
- 代码 review 能根据 common bug 或 invariant 卡片给出具体归因。
- 非 AC 反馈能结合错误类型和题型卡片给出调试方向。
- 复盘档可以引用题型总结，但不能大段搬运原文。

## 12. 产品范围

### 12.1 P0 必须完成

- 定义本地 source manifest 格式，能描述材料来源、语言、优先级、主要用途和授权备注。
- 支持人工整理或半自动生成的教练卡片入库。
- 支持 Markdown/txt 第一批材料导入、清洗、章节解析和基础切块。
- 支持 `knowledge_type`、`hint_level`、`has_full_solution`、题型标签和阶段过滤。
- 将检索结果接入做题工作台教练上下文，替换当前 `rag_deferred`。
- 在 Trace 中记录检索 query、过滤条件、命中片段、被过滤原因和最终注入片段。
- RAG Grounding Eval 从 `deferred` 升级为真实检查，并覆盖低提示档位不泄题。

### 12.2 P1 增强

- 将 `plan_path_card` 接入画像驱动计划补强和计划调整。
- 结合用户画像、近期复盘和题型路线生成更可解释的阶段计划。
- 支持按面试时间线和弱项自动选择材料路线。
- 将复盘沉淀的高质量摘要反向作为后续计划调整证据。

### 12.3 P2 扩展

- 面试表达卡片和轻量面试模拟联动。
- 更完整的材料质量评分和冲突处理。
- 面向研发验证的更大规模 RAG eval 集。
- 多语言代码实现注意点和语言特定 common bug 卡片。

## 13. 第一阶段不做

- 不做面向用户的通用资料搜索页。
- 不把 RAG 做成“问资料答资料”的聊天机器人。
- 不默认导入完整题解并在低提示档位使用。
- 不自动抓取 LeetCode、付费课程或未授权材料。
- 不把完整历史聊天、完整用户代码或敏感信息放入向量库。
- 不因为 RAG 命中结果就跳过用户画像、计划目标和训练状态机。
- 不要求第一阶段完成全自动高质量抽卡；可以先用人工整理卡片验证教练效果。

## 14. 验收标准

### 14.1 教练回答质量

- 追问档下，即使检索命中完整题解来源，AI 也不会输出题型答案、完整流程或伪代码。
- 方向档下，AI 能给出题型方向和思考路径，但不会直接给完整步骤。
- 关键档下，AI 能结合不变量或常见 bug 卡片给出可操作提示。
- 代码 review 中，AI 能把问题归因到明确 bug 类型或不变量破坏，而不是只给泛泛建议。
- 提交失败分析中，AI 能结合错误类型和当前题型给出优先检查路径。
- 复盘中，AI 能输出题型识别信号、关键思路、复杂度、常见误区和下一题建议。

### 14.2 可观测与评估

- Trace 页能看到 RAG 检索摘要、过滤条件、选中片段和最终注入状态。
- Eval runner 覆盖 RAG Grounding、Hint Leakage、Diagnosis 和 Code Review 的组合风险。
- 当检索结果被过滤或放弃注入时，系统记录稳定原因，例如 `hint_level_blocked`、`full_solution_blocked`、`low_quality`、`source_not_allowed`。

### 14.3 失败策略

- 检索无命中或命中质量低时，AI 教练仍能回退到非 RAG 流程。
- 检索服务异常时，工作台教练回复不能整体不可用，应记录 warning 并继续非 RAG 回复。
- 检索片段存在泄题风险但无法确定档位时，默认不注入。

## 15. 待澄清问题

- 第一批材料是否优先选择中文材料，还是混合中文和英文材料一起验证。
- 教练卡片是否先以人工 JSONL 维护，还是直接做半自动抽取流程。
- 用户可见回复是否需要展示来源短标记；第一阶段默认不展示完整引用面板。
- `problem_coach_card` 是否允许包含复盘档完整思路，还是必须拆成多个档位化 `hint_card`。
- RAG 命中与用户画像冲突时，优先听画像还是材料；第一阶段建议以当前训练事实和画像优先。
