# PRD：Agentic Coding Learning Coach 极简 MVP

## 1. 文档目的

本文档只描述产品需求：产品为谁解决什么问题、用户如何完成核心流程、当前 MVP 交付什么、不做什么。

技术架构、数据库、Docker 和命令契约分别见 `docs/architecture/` 与 `docs/dev-setup.md`。工作台和画像的详细产品要求见同目录专题 PRD。

## 2. 产品一句话

Agentic Coding Learning Coach 是一个面向算法刷题的 AI 教练。

它不定位成答案生成器，而是帮助用户明确训练目标、生成训练计划，并在做题过程中通过追问、分层提示、代码 review 和复盘，把一次刷题变成可诊断、可追踪、可改进的训练闭环。

## 3. 目标用户

刷题入门者：

- 看完题目后不知道从哪里开始。
- 不熟悉常见题型、数据结构和复杂度分析。
- 容易直接看答案，缺少独立推导过程。

刷过一轮但想提升的人：

- 能看懂题解，但独立做题不稳定。
- 面试时表达思路、复杂度和边界条件不够清晰。
- 常在实现细节、边界条件、调试和复盘上重复犯错。

## 4. 核心痛点

用户刷题时最缺的不是最终答案，而是稳定训练过程：

- 今天应该练什么。
- 卡住时应该先想什么。
- 什么时候需要提示，提示应该给到什么程度。
- 代码错了以后，应该定位思路问题、实现问题还是边界问题。
- 做完一题后，应该沉淀哪些经验，并决定下一题练什么。

普通大模型可以回答问题，但太容易直接给完整解法。这个产品要把 AI 约束成教练：先诊断，再引导，最后复盘。

## 5. 核心流程

当前 MVP 要跑通以下闭环：

```text
注册或登录
-> 配置模型 API 资产
-> 目标校准
-> 生成并确认当前学习计划
-> 选择计划题
-> 进入做题工作台
-> 用户描述思路、卡点或代码
-> AI 诊断并追问或分层提示
-> AI review 代码
-> AI 建议用户去 LeetCode 提交
-> 用户通过“LeetCode 已 AC”确认通过，或在聊天中粘贴未通过结果
-> 单题复盘
-> 更新学习画像
-> 推荐下一题
```

这条闭环是当前产品主线。其他能力如果不能服务这条主线，不进入 MVP。

## 6. 核心页面

### 6.1 登录、注册与 API 设置

提供本地账号能力，并允许用户保存自己的 OpenAI / OpenAI-compatible 模型 API 资产。用户没有可用模型资产时，应先完成设置，再进入目标校准或 AI 教练流程。

### 6.2 目标校准页

采集用户目标、时间线、每周投入、默认训练语言和弱项。AI 可以追问少量关键问题，并生成可确认的学习计划。

### 6.3 学习计划页

展示当前 active 学习计划，包括阶段目标、训练重点、推荐题目、推荐理由和每道题状态。

当前 MVP 只展示和操作当前计划，不提供学习计划历史页、计划版本切换 UI 或画像驱动补强入口。

计划题状态展示为：

- `未开始`：还没有有效训练痕迹。
- `编码中`：已经产生用户/教练对话、代码尝试或提交反馈，但尚未通过 LeetCode 官方 AC。
- `已AC`：由结构化“LeetCode 已 AC”动作或等价 AC 提交反馈产生。

学习计划页展示状态时应以训练会话和提交反馈为准，不能只依赖计划生成时写入的初始状态。

### 6.4 题库列表页

展示题目列表，支持按难度、标签、关键词和题单筛选。题库页是自由选题入口，学习计划页是主推荐入口。

### 6.5 做题工作台

工作台承载核心训练过程：上方展示题面，下方提供 ChatGPT 式 AI 教练对话。用户在对话中描述思路、粘贴代码、接收 review；LeetCode AC 通过明确动作结束本题，未通过结果直接在聊天中提供给教练。

详细要求见 `docs/prd/ai-coach-workbench-prd.md`。

### 6.6 复盘页

展示本题结果、主要卡点、提示使用、错误类型、复杂度分析、画像变化和下一步建议。

## 7. AI 教练边界

AI 教练必须遵守：

1. 默认不直接给完整答案。
2. 先理解用户当前思路，再决定是否提示。
3. 提示应分层递进，不能一步到位泄露完整解法。
4. 代码 review 优先定位问题和解释原因，不默认重写完整代码。
5. 复盘阶段可以解释完整思路，但重点仍是让用户理解推导过程。
6. 代码示例、方法签名和接近代码的伪代码应遵守用户选择的默认训练语言。
7. AI 的每次帮助都应尽量沉淀为用户画像或下一步训练建议。

提示档位：

| 档位 | 产品含义 |
| --- | --- |
| 追问档 | 只提问和澄清，不提示题型或数据结构。 |
| 方向档 | 提醒题型方向或可能的数据结构，不给完整流程。 |
| 关键档 | 提醒核心不变量、关键步骤或伪代码框架。 |
| 复盘档 | 可以解释完整思路，但仍不默认贴完整提交代码。 |

## 8. 训练模式

### 8.1 入门引导模式

适合刚开始刷题的用户。AI 可以更主动地拆题、解释题意、提醒常见题型，并引导用户先写暴力解法，再逐步优化。

### 8.2 独立训练模式

适合已经刷过一批题、希望提升独立解题能力的用户。AI 更克制，更像面试官，优先追问用户的思路、复杂度、边界条件和不变量。

### 8.3 面试模拟模式

后续探索，不作为当前 MVP 验收范围。后续如果重新启动，只做算法题面试模拟，不扩展到系统设计、行为面试或简历辅导。

## 9. MVP 范围

当前必须完成：

- 本地用户注册登录。
- 用户级模型 API 资产配置。
- 题库导入、题库浏览和中文题面展示。
- 目标校准。
- AI 生成并由用户确认学习计划。
- 从学习计划进入做题工作台。
- 入门引导和独立训练两种训练模式。
- AI 追问、分层提示和代码 review。
- AI 根据 AC 动作或聊天中的未通过反馈继续引导。
- 单题复盘。
- 用户学习画像更新。
- 下一题建议。

当前不做：

- 不做完整在线判题系统。
- 不做本地代码运行或样例执行。
- 不抓取 LeetCode 隐藏测试用例。
- 不自动提交 LeetCode。
- 不把完整题解作为默认上下文喂给 AI。
- 不做 RAG 知识库和向量检索。
- 不做 Trace 页面和研发观测面板。
- 不做全库备份恢复页面。
- 不做学习仪表盘。
- 不做画像驱动计划补强。
- 不做学习计划历史页、计划列表页或版本切换 UI。
- 不做复杂推荐算法，先用目标、题型、难度、历史卡点和计划阶段形成基础推荐。
- 不做轻量面试模拟的独立入口、倒计时、评分和面试复盘。
- 不扩展到系统设计、行为面试、简历润色等泛面试模块。

## 10. 成功标准

当前 MVP 成功标准：

- 新用户能完成目标校准，并得到一份可理解的学习计划。
- 用户能从学习计划进入一道题的完整训练过程。
- AI 能在不默认泄露完整答案的前提下，诊断卡点并推动用户继续思考。
- 用户能把 LeetCode 未通过结果直接发给教练，并得到下一步定位建议。
- 用户能通过明确 AC 动作结束训练，并看到单题复盘、画像变化和下一题建议。
- 核心路径有后端测试、前端测试和基础 eval 覆盖。

## 11. 后续恢复池

后续能力需要重新立项，不复用旧文档作为当前事实：

- RAG 教练知识库。
- Trace 和研发观测。
- 更完整的 eval 集。
- 学习仪表盘。
- 画像驱动计划补强。
- 学习计划历史和版本 UI。
- 本地 code-runner 和工具层。
